Security

How we protect your data and our infrastructure.

Our Security Commitment

Formation API handles sensitive business and personal information. We take a defense-in-depth approach to security, implementing multiple layers of protection across our infrastructure, application, and operational practices.

Data Encryption

In Transit

  • All API communications are encrypted using TLS 1.2 or higher
  • HTTP requests are automatically redirected to HTTPS
  • We support TLS 1.3 and prefer it when available
  • HSTS headers are enforced on all endpoints

At Rest

  • Database encryption using AES-256
  • Encrypted database backups stored in geographically separate locations
  • Sensitive fields (SSN last 4, EIN numbers) have additional application-layer encryption
  • API keys are stored as bcrypt hashes — the original key cannot be recovered

Infrastructure Security

  • Hosted on SOC 2 Type II certified cloud infrastructure
  • Network isolation between services using VPCs and security groups
  • DDoS protection at the network edge
  • Web Application Firewall (WAF) protecting against common attack vectors
  • Automated vulnerability scanning of dependencies and containers
  • Regular penetration testing by third-party security firms

Application Security

  • Input validation and sanitization on all API endpoints
  • Parameterized database queries (no SQL injection)
  • CORS restrictions on API endpoints
  • Content Security Policy (CSP) headers on web pages
  • Rate limiting per API key (configurable per-minute and per-day limits)
  • Scoped API key permissions (principle of least privilege)
  • Automatic session expiration and token rotation

Access Controls

  • Role-based access control (RBAC) for internal systems
  • Multi-factor authentication required for all internal access
  • Audit logging for all data access and modifications
  • Principle of least privilege for employee access
  • Regular access reviews and offboarding procedures

Payment Security

  • Payment processing through Stripe (PCI DSS Level 1 certified)
  • We never see, transmit, or store credit card numbers
  • All payment data flows directly between the client and Stripe

Incident Response

We maintain a documented incident response plan that includes:

  • 24/7 monitoring and alerting for security events
  • Defined escalation procedures and response team
  • Customer notification within 72 hours of confirmed data breach
  • Post-incident analysis and remediation
  • Regulatory notification where required by law

Vulnerability Reporting

We welcome responsible disclosure of security vulnerabilities. If you discover a security issue:

  1. Email security@formation.dev with details
  2. Do not publicly disclose the vulnerability until we've had a chance to address it
  3. Provide sufficient detail for us to reproduce the issue
  4. We aim to acknowledge reports within 24 hours and provide updates within 72 hours

Questions

For security-related questions, contact security@formation.dev.
