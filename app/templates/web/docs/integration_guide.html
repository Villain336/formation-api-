Integration Guide

This guide walks you through every step of a real integration. Every code example shows actual request payloads and the exact responses you'll get back.

Base URL: https://api.formation.dev/api/v1
All requests must include either a Authorization: Bearer <jwt> header or an X-API-Key: form_live_sk_... header.

Understanding the Pricing Flow

Before creating an order, you can get an exact price quote. This is useful for showing your users the total cost before they commit.

POST /orders/pricing
curl -X POST "https://api.formation.dev/api/v1/orders/pricing?\
entity_type=llc&\
state=DE&\
processing_speed=standard&\
include_registered_agent=true&\
include_ein=true&\
include_operating_agreement=false"
Response: 200 OK
{
  "state_fee": 9000,
  "service_fee": 22800,
  "expedited_fee": 0,
  "registered_agent_fee": 9900,
  "total_amount": 41700,
  "currency": "usd",
  "breakdown": {
    "state_filing_fee": 9000,
    "formation_service_fee": 14900,
    "state_expedited_fee": 0,
    "registered_agent_first_year": 9900,
    "ein_service": 7900,
    "operating_agreement": 0
  }
}

All amounts are in cents. Divide by 100 to get dollars. So 41700 = $417.00.

2. Process Payment

POST /payments/create-intent
curl -X POST https://api.formation.dev/api/v1/payments/create-intent \
  -H "X-API-Key: form_live_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"order_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"}'
Response: 200 OK
{
  "client_secret": "pi_3abc123_secret_xyz789",
  "payment_intent_id": "pi_3abc123",
  "amount": 41700,
  "currency": "usd"
}

Use the client_secret with Stripe.js on your frontend to complete the payment. When Stripe confirms the payment, our webhook handler automatically moves the order to paid status.

Frontend Payment (Stripe.js)

your-frontend/checkout.js
const stripe = Stripe('pk_live_your_publishable_key');
const { error } = await stripe.confirmPayment({
  clientSecret: 'pi_3abc123_secret_xyz789',
  confirmParams: {
    return_url: 'https://yourapp.com/order/confirmed',
  },
});

3. Track Order Status

GET /orders/:id
curl https://api.formation.dev/api/v1/orders/a1b2c3d4-... \
  -H "X-API-Key: form_live_sk_..."

The status field progresses through:

draft → pending_payment → paid → processing → filed → completed

Error Handling

Formation API returns consistent error responses:

Error Responses
// 400 Bad Request - Invalid input
{
  "detail": "Formation of llc is not available in XX"
}

// 401 Unauthorized - Bad or missing API key
{
  "detail": "Invalid authentication credentials"
}

// 404 Not Found - Resource doesn't exist
{
  "detail": "Order not found"
}

// 422 Validation Error - Missing required fields
{
  "detail": [
    {
      "loc": ["body", "business_name"],
      "msg": "field required",
      "type": "value_error.missing"
    }
  ]
}

Production Checklist

Before going live, verify:

  • Switch from form_test_ to form_live_ API keys
  • Set up webhook endpoint with signature verification
  • Store API keys in environment variables (never in code)
  • Configure Stripe with your live publishable/secret keys
  • Set appropriate API key scopes (principle of least privilege)
  • Enable key expiration (90 days recommended) and set up rotation
  • Handle all error status codes gracefully in your UI
  • Add retry logic with exponential backoff for 5xx errors
  • Test the complete flow end-to-end in test mode first
  • Review the Compliance Guide for legal requirements
