Security Best Practices

This guide covers how to securely integrate with the Formation API, protect sensitive data, and meet regulatory requirements when handling business formation data.

Compliance requirement: Business formation involves personally identifiable information (PII) including names, addresses, SSNs, and financial data. You have a legal obligation to protect this data under state and federal law.

API Key Security

Key Storage

  • Never hardcode API keys in source code, configuration files committed to version control, or client-side JavaScript.
  • Use environment variables or a secrets manager (AWS Secrets Manager, HashiCorp Vault, GCP Secret Manager, Doppler).
  • Restrict file permissions on any files containing API keys to the application user only.
Correct: Use environment variables
# .env (never commit this file)
FORMATION_API_KEY=form_live_sk_a1b2c3d4...

# Python
import os
api_key = os.environ["FORMATION_API_KEY"]

# Node.js
const apiKey = process.env.FORMATION_API_KEY;

Key Lifecycle Management

  1. Rotate keys every 90 days using the /api-keys/{id}/roll endpoint.
  2. Set expiration dates on all keys using expires_in_days.
  3. Use separate keys for each service/environment (don't share keys between staging and production).
  4. Monitor usage via the total_requests and last_used_at fields. Alert on unexpected spikes.
  5. Revoke immediately if a key is compromised. Use DELETE /api-keys/{id}.

Principle of Least Privilege

Only grant the scopes each key needs:

// Backend order service - only needs order operations
{
  "scopes": ["orders:read", "orders:write", "states:read"]
}

// Reporting dashboard - read-only access
{
  "scopes": ["orders:read", "payments:read", "compliance:read"]
}

// Webhook processor - minimal permissions
{
  "scopes": ["webhooks:read", "webhooks:write"]
}

Data Protection

Data in Transit

  • All API communication is over TLS 1.2+. We reject HTTP connections.
  • Pin our SSL certificate if your platform supports it.
  • Verify the API hostname matches api.formation.dev.

Data at Rest

  • All data is encrypted at rest using AES-256.
  • Sensitive fields (SSN last 4, EIN numbers) are additionally encrypted at the application layer.
  • Database backups are encrypted.

Sensitive Data Handling

  • SSN data: We only accept the last 4 digits of SSN. Never send full SSNs. We use this only for EIN applications.
  • API keys: Stored as bcrypt hashes. We cannot retrieve your key after creation.
  • Payment data: Handled entirely by Stripe. We never see or store credit card numbers (PCI DSS compliant).
  • Personal data: Member names, addresses, and contact info are stored encrypted and access-logged.

Webhook Security

All webhook payloads are signed with HMAC-SHA256. Always verify the signature before processing:

# Python verification example
import hmac
import hashlib

def verify_webhook(payload: bytes, signature: str, secret: str) -> bool:
    expected = hmac.new(
        secret.encode('utf-8'),
        payload,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(f"sha256={expected}", signature)

# In your webhook handler:
signature = request.headers.get('X-Formation-Signature-256')
if not verify_webhook(request.body, signature, webhook_secret):
    return Response(status_code=401)

IP Allowlisting

For enterprise plans, you can restrict API key usage to specific IP addresses. Contact support to configure IP allowlists for your keys.

Audit Trail

Every API key tracks:

  • last_used_at — Timestamp of last API call
  • last_used_ip — IP address of last API call
  • total_requests — Lifetime request count

Review these regularly for unauthorized access patterns.

Regulatory Compliance

When using the Formation API for business formation services, you and your platform should be aware of:

  • FinCEN BOI Reporting: As of 2024, newly formed entities must file Beneficial Ownership Information reports. Our API auto-creates compliance tasks for this.
  • State-specific requirements: Some states (NY, AZ, NE, PA) require publication in newspapers. Our compliance tracking flags these.
  • Anti-Money Laundering (AML): If you're offering formation services to the public, consider implementing KYC checks on your end before submitting orders.
  • Privacy laws: Member PII is subject to CCPA (California), state privacy laws, and potentially GDPR if serving EU customers forming US entities.

Incident Response

If you suspect a security incident:

  1. Immediately revoke any potentially compromised API keys.
  2. Contact us at security@formation.dev.
  3. Review your API key usage logs for unauthorized activity.
  4. Rotate all keys as a precaution using the roll endpoint.
